# מיגרציות

- מיגרציות מוחלות ידנית ב-SQL Editor. הפנקס `schema_ledger` הוא המקור לרצף, לא שמות הקבצים.
- `schema_ledger` מערבב מוסכמות מספור (`0001`-`0050` ו-`fix-YYYY-MM-DD-x`). למיין תמיד לפי `applied_at`, לעולם לא לפי `version`.

## הטקס — שלושה צעדים, לא שניים

1. **להריץ** את המיגרציה ב-SQL Editor.
2. **לרשום** ב-`schema_ledger` (הרישום נמצא בתוך אותו בלוק `DO` אטומי, כך ששינוי ורישום נופלים או עוברים יחד).
3. **לרענן טיפוסים** — ולקמט יחד עם המיגרציה:

   ```
   npx supabase gen types typescript --project-id teobjwdszasavvmvukfb > src/lib/supabase/database.types.ts
   ```

   `--project-id` תמיד מפורש, לעולם לא `<ref>` ולעולם לא בהשמטה. הפרויקט הוא
   **פרנקפורט** (`teobjwdszasavvmvukfb`). בלי הדגל ה-CLI נופל חזרה על
   `supabase/.temp/linked-project.json` — קובץ שהוא gitignored, לוקאלי לכל מכונה,
   ואינו נראה בשום code review. ב-20.8.2026 הוא עדיין הצביע על פרויקט סינגפור
   הישן (`vjnpczakfftvxeeaesmi`) חודשים אחרי ההגירה, והוסר. פקודה בלי הדגל הייתה
   מייצרת קובץ טיפוסים מסכימה זרה ומקמטת אותו — בשקט, בלי שגיאה. עם הדגל, מצב
   ה-`link` של המכונה לא רלוונטי.

צעד 3 אינו אופציונלי, ואינו מסתמך על זיכרון: `npm run prebuild` מריץ את
[`scripts/check-schema-drift.mjs`](../../scripts/check-schema-drift.mjs), שמשווה את הקובץ המקומט מול הסכימה החיה
(דרך `GET /rest/v1/`, בלי CLI ובלי טוקן) ומפיל את הבילד על פער.

**למה זה קריטי:** קובץ טיפוסים מיושן גרוע מאין טיפוסים.
עמודה שנוספה ולא רועננה → `tsc` דוחה עמודה שקיימת באמת (רועש, בטוח).
עמודה שנמחקה ולא רועננה → השם הישן ממשיך לעבור `tsc` והקוד נופל ב-42703
ב-runtime — בדיוק הכשל שהטיפוסים אמורים למנוע, עכשיו עם קובץ שמעיד עליו.

הבדיקה **fail-open**: מפתח חסר, נקודת קצה לא זמינה, timeout או קובץ שלא ניתן
לנתח — כולם מדלגים ומחזירים 0. רק פער מאומת מפיל בילד. עקיפה: `SKIP_SCHEMA_DRIFT_CHECK=1`.
